# Branching-Strategie

TechStyle verwendet **GitHub Flow**: kurze Arbeitsbranches, Pull Requests und `main` als auslieferbaren Stand. Ein zusätzlicher dauerhafter `develop`-Branch ist für das kleine Projektteam nicht erforderlich.

Die vollständigen Regeln zu Branch-Namen, Merge-Varianten, Reviews, Releases und Konflikten stehen in [CONTRIBUTING.md](../CONTRIBUTING.md). Diese Datei dient nur noch als Verweis, damit nicht zwei widersprüchliche Strategien gepflegt werden.
